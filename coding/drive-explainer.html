The four steps in the code

1. Read the sticks

Three numbers from -1 to 1: drive, slide and turn.

2. Mix

Combine them into 4 wheel powers, one line per wheel.

3. Scale down

If any power is past 1.0, divide all four by the biggest.

4. Send

Give each motor its power with setPower.

Start from FIRST's sample BasicOmniOpMode_Linear.java, which does the same four steps. From laptop to robot shows where FIRST's samples are and how to copy one.

How four wheels slide sideways

Rollers push at an angle

A mecanum wheel has small rollers set at 45 degrees, so it pushes diagonally, not straight. Spin diagonal pairs opposite ways, and the forward and backward pushes cancel while the sideways pushes add up.

Slide right (lateral)+−−+
Turn clockwise (yaw)+−+−

The whole pattern

Each wheel's power is axial, plus or minus lateral, plus or minus yaw, using the signs in its column. That's all the four Power = lines in the code are.

Why scale down?

Forward all the way (1) and right halfway (0.5) asks two wheels for 1.5 and two for 0.5. A motor stops at 1.0, so without scaling the wheels get 1, 0.5, 0.5, 1: the strong pair lost a third of its push but the weak pair lost nothing, and the robot drives about 18 degrees off straight instead of the 27 you asked for. Dividing all four by 1.5 gives 1, 0.33, 0.33, 1: the same balance as the sticks, just as fast as the motors allow. Step 7 of the tour shows both robots side by side.

Try it in the Virtual Robot

New to the Virtual Robot? Set it up first.

  1. Open the Virtual Robot project in Android Studio and click Git > Pull to get the latest version. Run Main, pick Mecanum Odometry Bot, then Manual Drive. INIT, START, and drive with the on-screen gamepad.
  2. Remove the minus sign in front of gamepad1.left_stick_y.Predict first: what happens when you push the left stick up? Put the minus sign back afterward.
  3. Delete the scale-down block (the max lines and the if).Predict: push forward and turn hard at the same time. Does the robot turn as much as before? Watch the telemetry numbers.
  4. Slow the turning down. Change the yaw line to gamepad1.right_stick_x * 0.5.Predict: what's the fastest the robot can spin now?
  5. Move turning to the left stick. Some drivers like forward and turn on one stick. Swap which stick feeds lateral and yaw.Predict: which stick slides the robot now? Which way do you like better?

Questions you might ask

I push forward and the robot slides or spins. Why?

A motor is reversed the wrong way or plugged into the wrong port. FIRST's sample says to test one wheel at a time: get each motor on the right port first, then fix the setDirection lines until every wheel rolls forward when you push the left stick forward.

Why are the left motors reversed?

The motors on the left face the opposite way to the ones on the right. Reversing them means "positive power" rolls every wheel forward, so the mixing lines stay simple.

Why does the robot keep its own "forward" when it turns?

This code is robot-centric: forward means the way the robot faces. Field-centric driving uses the gyro so "up the stick" always means "away from the driver", whichever way the robot faces. That needs one more step of math, and Pedro Pathing has it built in.

How fast does this loop run?

Many times a second, as fast as the Control Hub gets through it. That's why nothing in a TeleOp loop should wait or sleep(): while it waits, the sticks aren't being read.
